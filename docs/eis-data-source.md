# Источник исторических данных ЕИС — результат Этапа 0

> **ИТОГ: источник работает.** Интеграционный сервис ЕИС доступен с
> боевого сервера, архивы скачиваются и разбираются. Рабочий рецепт —
> в разделе «Как это работает» ниже. Остальной текст — история поиска.

## Как это работает (проверено 20.09.2026)

Точка входа: `https://int.zakupki.gov.ru/eis-integration/services/getDocsIP`,
только через прокси (прямой доступ с сервера закрыт), обычный TLS.

⚠️ **Клиент не должен предлагать ГОСТ-шифры.** Если предложит — сервер
их выберет, и рукопожатие оборвётся на session ticket. На сервере
OpenSSL 3 без ГОСТ, там всё хорошо. На macOS python и openssl
слинкованы с LibreSSL, у которого ГОСТ есть: там нужен
`ctx.set_ciphers('ALL:!GOST:!aGOST:!kGOST')` — одного `!GOST` мало.

Запрос — SOAP, токен в заголовке `individualPerson_token`.
**`elementFormDefault="unqualified"`: все вложенные элементы без
префиксов**, префикс только у корневого `getDocsByOrgRegionRequest`.
Иначе код 28 «Ошибка валидации по интеграционной схеме».

```xml
<ws:getDocsByOrgRegionRequest xmlns:ws="http://zakupki.gov.ru/fz44/get-docs-ip/ws">
  <index><id>UUID</id><createDateTime>ISO8601</createDateTime><mode>PROD</mode></index>
  <selectionParams>
    <orgRegion>77</orgRegion>              <!-- 2 цифры КЛАДР -->
    <subsystemType>RGK</subsystemType>     <!-- реестр госконтрактов -->
    <documentType44>contract</documentType44>
    <periodInfo><exactDate>2026-09-17</exactDate></periodInfo>
  </selectionParams>
</ws:getDocsByOrgRegionRequest>
```

Ответ — список `<archiveUrl>`; **ссылки завёрнуты в CDATA**, наивный
regex их не видит. Скачивание — обычный GET с тем же токеном в
заголовке.

Замер на Москве за один день: **13 архивов, в первом 1,9 МБ и 100 XML**,
корневой тег `export` → `contract`. Из одного файла разобрано:

```
реестровый номер   03732006585
цена контракта     100000.00
дата заключения    2026-09-15
ИНН поставщика     7709568163
наименование       ГБУ города Москвы «Жилищник ...»
```

Рабочие скрипты на сервере: `/opt/eis/` (`call.py`, `fetch_arch.py`,
`parse.py`), XSD — `/opt/eis/getDocsIP.xsd`.

### Что осталось выяснить

`documentType44` для **протоколов подведения итогов**. Официальное
приложение к инструкции отсылает к Альбому ТФФ, раздел 2.9.19 —
в самом документе списка для 44-ФЗ нет. Перебором не нашлось:
`protocols`, `epProtocol`, `epProtocolEF44`, `purchaseProtocol`,
`protocolEF`, `epNotificationEF44` (все с `PRIZ`) → `noData`.
Для 223-ФЗ соглашение известно (`purchaseProtocol*`, Приложение 2).
Контракты уже дают ИНН победителя и цену — половину нужных метрик.

## Вариант 1. FTP — мёртв

`ftp.zakupki.gov.ru` не существует в DNS: проверено на 8.8.8.8, 1.1.1.1,
77.88.8.8, 94.140.14.14 и с боевого сервера в РФ. Контрольный
`zakupki.gov.ru` резолвится (95.167.245.92). Поддоменов `ftp2`, `fz44`,
`files` тоже нет.

## Вариант 2. Раздел «Открытые данные» — схлопывается в вариант 1

Каталог наборов жив и содержит `Protocols` — протоколы определения
поставщика по 44-ФЗ, по каждому региону. Но в паспорте **каждого**
набора в поле «Гиперссылка (URL) на набор» стоит адрес мёртвого FTP:

```
44-ФЗ:  ftp://free:free@ftp.zakupki.gov.ru/fcs_regions/<Регион>/protocols/
223-ФЗ: ftp://fz223free:fz223free@ftp.zakupki.gov.ru/out/published/<Регион>/<тип>/
```

Структура путей и учётные данные из ТЗ подтвердились документально, но
скачать по ним нечего. HTTP-входа в то же дерево нет (404 на
`/fcs_regions/…`, `/fz44/fcs_regions/…`, `/opendata/fcs_regions/`).
**Паспорта наборов не актуализированы** — рекламируют доступ, которого
нет почти два года.

## Замена FTP — SOAP-сервисы. ДОСТИЖИМО

Два метода:

- **`getDocsIP`** — требует токен в SOAP-заголовке
  `<individualPerson_token>`. У владельца токен есть, действует до
  17.03.2027.
- **`getDocsMis2`** — по официальной инструкции **не требует ни
  регистрации, ни электронной подписи**. Лимит 5000 запросов/час,
  заявлен как временный на период перехода. Ответ отдаёт `archiveUrl`
  со ссылкой на архив — то есть это прямой функциональный аналог FTP.
  [Инструкция, PDF](https://zakupki.gov.ru/epz/main/public/download/downloadDocument.html?id=41500)

Путь у обоих: `https://int.zakupki.gov.ru/eis-integration/services/<метод>`

### Что показал живой замер TLS (с Mac, российский IP)

```
int.zakupki.gov.ru              Protocol TLSv1.2
                                Cipher   GOST2012256-GOST89-GOST89
                                No client certificate CA names sent   ← !
                                Verify return code: 21 (издатель — УЦ Казначейства)

int44-ttls-cert.zakupki.gov.ru  Acceptable client certificate CA names ← mTLS
int44.zakupki.gov.ru            EOF — хост выведен из эксплуатации
zakupki.gov.ru                  TLSv1.2 ECDHE-RSA-AES128-GCM (обычный TLS, контроль)
```

**Главное: `int.zakupki.gov.ru` не запрашивает клиентский сертификат.**
Значит неизвлекаемый КЭП на физическом токене — НЕ препятствие. Он был
нужен один раз, при выпуске токена, а не для вызовов сервиса.

Взаимный TLS требуется только на `int44-ttls-cert`, и туда идти незачем.

### Что остаётся сделать

1. **ГОСТ-совместимый TLS-стек на сервере.** Сейчас его нет:
   `openssl 3.0.13`, ГОСТ-шифров в сборке 0, движок gost не подключён.
   Варианты: КриптоПро CSP + stunnel как ГОСТ-прокси, либо открытый
   `gost-engine` к OpenSSL.
2. **Корневой сертификат УЦ Федерального казначейства** — для проверки
   цепочки (сейчас `Verify return code: 21`).
3. **Сетевой доступ.** С боевого сервера `int.zakupki.gov.ru` напрямую
   не открывается (как и `zakupki.gov.ru`) — ЕИС недоступен оттуда без
   прокси. См. раздел ниже.

## Вариант 3. Разбор карточки процедуры — работает, но как запасной

Проверено на живой процедуре `0338300003326000140`.

```
https://zakupki.gov.ru/epz/order/notice/ea44/view/supplier-results.html?regNumber=<20 цифр>
   → 302 → .../ea20/...   (тип процедуры подставляется редиректом, нужен -L)
```

| Поле | Статус | В примере |
|---|---|---|
| `purchase_number` | есть | 0338300003326000140 |
| НМЦК | есть | 917 606,00 ₽ |
| `winner_price` | есть | 610 207,99 ₽ |
| `protocol_date` | есть | 20.09.2026 |
| `bids_submitted` | по строкам таблицы «Предложения участников» | 1 |
| `winner_name` | **нет** | участник обезличен номером `121942620` |
| `winner_inn` | **нет на этой странице** | только из реестра контрактов |

Падение цены считается сразу: 610 207,99 / 917 606 = **−33,5%**.

Ограничения: один-два HTTP-запроса на процедуру вместо одного архива на
регион за месяц; победитель обезличен до заключения контракта;
`bids_submitted` проверен только на одноза́явочной процедуре.

## Сетевой доступ к ЕИС — отдельная проблема

С боевого сервера ЕИС напрямую не открывается, только через прокси. На
20.09.2026 **все пять прокси отдают код 000 к zakupki.gov.ru**, при том
что сами прокси живы (возвращают свой IP через api.ipify.org). ЕИС
заблокировал эти адреса.

Домашний IP (МГТС, 109.252.x) при этом работает штатно — то есть
блокируются адреса дата-центров, а не регион.

Это ограничивает и вариант 3, и будущий ГОСТ-канал.

## Рекомендация

Идти в **`getDocsMis2` / `getDocsIP` на `int.zakupki.gov.ru`** — это
полноценная замена FTP, при которой Discovery по всему дереву ОКПД2
возможен. Ключевая работа — поднять ГОСТ-TLS, а не искать платный
источник.

Вариант 3 оставить как запасной и как валидатор парсера.

Платный источник (вариант 4 по ТЗ) нужен, только если ГОСТ-канал не
поднимется. Из проверенных единственный, где публично перечислены все
нужные поля (число заявок, цена и ИНН победителя, ОКПД2) — **DaMIA**,
9 000–36 000 ₽/год за 1000–10 000 запросов; для полного дерева ОКПД2
этого лимита, скорее всего, не хватит.
